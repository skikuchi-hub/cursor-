# 写真の自動チェック（毎日）

巡回報告に添付された機械の写真を、Claude のルーティン（定期実行）が毎日読んで、
空き部屋・POP・陳列の状態をスプレッドシート「クレーンゲーム日報」の「写真」タブに書き戻す仕組み。

## 流れ

1. スタッフがアプリ「クレーンログ」で巡回報告に写真を添付。**補充前**（着いてすぐ）と**補充後**（補充・入れ替えが終わったあと）の 2 種類
   - 補充前：前回の補充後から今回までに「何が取られたか」（空いた部屋）を見る
   - 補充後：「何をどこに入れたか」（お客さんがこれから見る状態。位置・POP の分析はこちらが元データ）
2. Apps Script が Drive「クレーンログ写真／店舗／yyyy-MM」に保存し、「写真」タブに 1 行追加（A〜H 列）
3. 毎日 22:07（日本時間）にルーティンが起動し、「写真」タブの I 列（チェック日時）が空の行を読む
4. 写真を Drive から取得して目視判定し、結果 JSON を Drive「クレーンログ写真／_チェック結果」に置く
5. Apps Script の `importPhotoChecks()` が JSON を「写真」タブ I〜Q 列に取り込む
   （アプリ起動時に 10 分に 1 回自動で呼ばれる。手動なら Apps Script エディタから実行）
6. ルーティンは菊地さんに短い報告（通知）を出す。報告との食い違い・陳列の問題があるときだけ詳しく書く

## 「写真」タブの列

| 列 | 内容 | 書く人 |
|---|---|---|
| A 訪問日 / B 店舗 / C 機械 / D 担当 | 報告の内容 | Apps Script |
| E 種別 | `補充前` / `補充後` | Apps Script |
| F 写真URL / G ファイルID / H 登録日時 | Drive の写真 | Apps Script |
| I チェック日時 | 判定した日時 | 自動チェック |
| J 空き部屋 | 空いている部屋番号（例 `5,6`） | 自動チェック |
| K 空き数 | その数 | 自動チェック |
| L 報告の払出 | 同じ記録の「出た」数（BOX は out の枠数、4人機は取られた数の合計） | 自動チェック |
| M 照合 | `一致` / `不一致` / `不明`。補充前＝空き部屋と報告の払出。補充後＝全部屋に景品が入っているか、入れ替え枠と矛盾しないか | 自動チェック |
| N POP数 | 訴求札（人気No.1・数量限定・手書き札など）の数 | 自動チェック |
| O 陳列スコア | 1〜5（5＝全部屋に景品、POP あり、崩れなし、ガラスきれい） | 自動チェック |
| P 所見 | 気づいた点を 1〜2 文 | 自動チェック |
| Q 競合メモ | 隣の機械に何があるか | 自動チェック |

## 結果 JSON の形（_チェック結果 に置くファイル。名前は `check_YYYYMMDD_HHmm.json`）

```json
{
  "checkedAt": "2026-10-08T22:10:00+09:00",
  "items": [
    { "fid": "<DriveのファイルID（F列）>", "emptyRooms": [5, 6], "emptyCount": 2,
      "reportedPays": 2, "match": "一致", "popCount": 9, "score": 4,
      "note": "5・6番が空。上段と中段中央に人気札。じゃがりこ（11番）は食品なので回転確認。",
      "competitor": "左にカプセル機（1回100円）" }
  ]
}
```

取り込み済みのファイルは Apps Script が `done_` を先頭に付けて名前を変える。

## 判定のルール

- 空き部屋：景品が見えず背景だけの部屋。扉が開いている・景品が倒れて見えないだけなら「不明」寄りに書く
- **補充前** の照合：BOX 機は「出た」枠の数と空き部屋の数が同じなら `一致`。4人機は部屋ごとの残り数が写真と矛盾しなければ `一致`
  - 同じ店舗・機械の **前回訪問の補充後写真** があれば見比べて、空いた部屋＝取られた景品、景品が変わっている部屋＝入れ替え、と区別する
  - 空き部屋ゼロで報告は払出あり、なら補充後に撮った可能性が高いので `不明` にして、所見に「補充後の写真の可能性。補充前に撮る」と書く
- **補充後** の照合：全部屋に景品が入っていれば `一致`。空きが残っていれば `不一致`（所見に部屋番号）。
  同じ訪問の補充前写真と見比べ、入れ替わった部屋が報告の補充・入れ替えと合っているかも見る
- POP：値札以外の訴求物（人気No.1、数量限定、手書き、キャラ札）を数える
- スコア：5＝全部屋に景品・POP あり・崩れなし／4＝軽微／3＝空き部屋 2 つ以上 or POP なし／2＝崩れや汚れが目立つ／1＝半分以上が空
- 景品名は写真から無理に読まない。部屋番号と見た目だけ書く（名前はアプリの部屋別ログにある）

## 週1に戻すとき

データが貯まり、毎日追う必要がなくなったら、ルーティンの cron を週1（例：月曜 22:07）に変える。
Claude Code のスレッドで「写真チェックのルーティンを週1にして」と頼めばよい。
